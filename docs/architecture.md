# Architecture

The mechanisms shared by every feature. Feature specs say what happens; this file says how. One H2 per mechanism.

## Pieces

| Piece | File | Job |
|---|---|---|
| Content script | `extension/content.js` | Everything: modes, input, rendering, anchoring, storage, toolbar. Top frame only. |
| Content styles | `extension/content.css` | The overlay canvases and the shadow host. Nothing else. |
| Background | `extension/background.js` | Relays the Safari toolbar button tap to the content script. |
| Manifest | `extension/manifest.json` | Manifest v3. Permissions: storage, activeTab, host `<all_urls>`. |
| Wrapper app | `Inkover/` | Generated by `xcrun safari-web-extension-converter`. Holds no logic. Regenerate rather than edit. |
| Dev harness | `dev/` | A page that loads the content script in any desktop browser with the mouse standing in for the Pencil. Mechanics only; never pressure or palm behaviour. |

No bundler, no dependencies, no build step. The content script is one file, organised into sections whose headings match the H2s below.

The harness sets `window.__inkoverDev` before the script loads. With that flag, mouse pointer events count as pen events. Nothing else differs, and the flag is never set by the extension itself.

## Mode state machine

Three states, per tab: Off, Unlocked and Locked. Transitions and their triggers are the behaviour rules in [[modes-and-lock]]. The state lives in one variable; every other section reads it and only the mode section writes it. Entering Off removes the canvases and toolbar host from the DOM. Leaving Off creates them. Moving between Unlocked and Locked touches nothing but the toolbar and the iframe shields, so a stroke in progress survives an Unlock tapped by a finger.

## Input routing

The overlay canvases always have `pointer-events: none`. Nothing is ever blocked by the canvas itself. Capture is done with listeners on `window` in the capture phase, and every one of them returns at once unless the mode is Locked:

- `pointerdown`, `pointermove`, `pointerup`, `pointercancel`: `pointerType === "pen"` is cancelled with `preventDefault()` and `stopImmediatePropagation()`, then fed to the active tool. `pointerType === "touch"` is cancelled and stopped the same way so page scripts see nothing. Anything else, a trackpad for instance, is let through.
- `touchstart`, `touchmove`, `touchend`, `touchcancel`, registered with `passive: false`: every touch outside the toolbar is cancelled and stopped, stylus and finger alike. This is what stops Safari from scrolling, selecting text or starting Scribble from the Pencil, and from scrolling under a palm. Touch identifiers are tracked so Unlock can tell whether anything is still down.
- Events whose `composedPath()` includes the toolbar host are always let through.
- `keydown` for Escape, Cmd+Z and Shift+Cmd+Z, only when `document.activeElement` is body or null. Cmd+Z works Unlocked too.
- `click`: cancelled when it comes from a pen or a touch, or within 1.5 s of a captured pointerdown. On iPad the cancelled `touchstart` already prevents the click; this closes the same gap on desktop, where the dev harness has no touch events.

Use `getCoalescedEvents()` on `pointermove` when present. Pressure comes from `event.pressure`.

Iframes do not bubble events to the parent, so while Locked a shield `div` with `pointer-events: auto` is placed over the bounding rect of every visible iframe, re-measured on every render. Unlocked, there are no shields and the iframe is native.

## Coordinates and rendering

Two canvases, both `position: fixed`, sized to the visual viewport, scaled by `devicePixelRatio`:

- Ink canvas: all committed strokes. Redrawn whenever the view or the ink changes.
- Effects canvas: the stroke in progress, snap previews, the eraser cursor, the spotlight dim and the trail. Runs a `requestAnimationFrame` loop only while something on it is animating.

Points arrive in client coordinates and are converted immediately to document coordinates by adding the layout scroll offsets, so a stroke drawn while a finger scrolls follows the content. Both canvases are positioned at the visual viewport's offset and sized to it, and the canvas transform maps document coordinates to canvas pixels through `visualViewport.scale` and `devicePixelRatio`. Pinch-zoom therefore needs no special casing anywhere else.

Each stroke's geometry is built once per anchor placement as a `Path2D` in document coordinates and cached by the anchor rect. Scrolling changes only the canvas transform and never rebuilds a path. Anchor rects are measured in document space and cached until an epoch counter changes.

The epoch changes on: the mutation observer, the resize observers, window resize, orientation change, `scrollend`, a throttled scroll tick every 100 ms, any change to ink, and a 1 s interval as a safety net for layout changes nothing observed. Every trigger coalesces into one `requestAnimationFrame`.

Pen strokes are drawn as a filled outline built from per-point widths, midpoint-smoothed with quadratic curves. Highlighter strokes are one stroked path at fixed width with `globalAlpha` applied to the path as a whole.

## Anchoring

Behaviour and edge cases are in [[anchoring]]. The mechanism:

1. Candidate: `document.elementsFromPoint()` at the stroke's first point, skipping Inkover's own nodes. Walk up from the top-most hit until an element is block-level, at least 16 px tall, and has non-empty text or is `img`, `video`, `canvas`, `svg` or `picture`. Reaching `body` means anchor kind `root`.
2. Locator: if the element has an id unique in the document, kind `id`. Otherwise kind `path`, a selector built from tag and `:nth-of-type` from the nearest unique-id ancestor or `body`. Always store `text`: the first 60 characters of the element's normalised text content, and `width`: the element's bounding width at draw time.
3. Resolve: look up by id or path, verify `text` matches. On failure, scan `document.querySelectorAll(tag)` for the first element whose normalised text starts with `text`, and rewrite the locator. Resolutions are cached per stroke and dropped on every mutation batch.
4. Visible: the element is connected, `checkVisibility()` is true, and its rect has non-zero size. Otherwise the stroke is skipped this frame.
5. Position: `x = rect.left + dx × rect.width / width`, `y = rect.top + dy`.

One `MutationObserver` on `document.body` watches `childList`, `subtree`, and the attributes `class`, `style`, `hidden`, `aria-hidden`, `aria-selected`, `aria-expanded`, `open`. Records whose target is one of Inkover's own nodes are ignored. One `ResizeObserver` observes every distinct resolved anchor. Repair scans share a budget of 3 ms per 100 ms window; a stroke that misses the budget is left unresolved for that frame and a retry is scheduled for the next window.

The anchor element for a stroke is chosen at Pencil-down, not Pencil-up, so a stroke whose start has scrolled off screen by the time it ends still anchors to what was under its first point.

## Storage

`browser.storage.local`, key `ink:<page key>`, value `{ v: 1, strokes: [...] }`. Global settings live under key `settings`: tool, previous tool, pen and highlighter colours, one custom colour per tool, pen width, highlighter width, spotlight band, label and compact preferences, toolbar edge and position. Saves are debounced 500 ms and flushed on `pagehide`. Rules for limits and versions are in [[persistence]].

## Stroke model

```js
{
  id: "uuid",
  tool: "pen" | "highlighter",
  color: "black" | "#8e44ad",  // a palette key from the toolbar spec, or a hex colour from the picker
  width: 3,                    // pen base or highlighter width in CSS px; ink saved with an old size key is converted on load
  straight: false,             // highlighter snap applied
  anchor: { kind: "id" | "path" | "root", value: "...", text: "...", width: 612 },
  points: [[dx, dy, pressure], ...],   // CSS px relative to anchor top-left
  created: 1757030400000
}
```

Undo entries are `{ type: "add" | "remove" | "clear", strokes: [...] }`. The eraser and Clear produce `remove` and `clear`; they never store anything themselves.

## Toolbar host

One `div` appended last in `body`, `position: fixed`, maximum z-index, holding an open shadow root with the toolbar markup and its own stylesheet. The host is re-appended if a mutation batch finds it disconnected. Its position is stored relative to the visual viewport edge it is snapped to, so it survives rotation.

Two things about the page can break an overlay, and both were met on claude.ai:

- The page's Content-Security-Policy applies to style attributes the extension sets. Colours and sizes are therefore set through `element.style`, which is CSSOM and outside the policy's reach. The toolbar stylesheet is installed twice: as a constructed `CSSStyleSheet` adopted by the shadow root, and as a `<style>` element. Safari honours the element for content scripts even under a strict policy; the constructed sheet covers a page that blocks the element. Whichever applies, the toolbar is styled.
- The host, the canvases and the shields are elements in the page's DOM, so page selectors like `body > div` match them. Every property in `content.css` is `!important`, and the transforms and sizes set from script use `setProperty` with the important flag. `content.css` never uses `all: initial`, because that would also wipe what the script sets and, if Safari ever served a stale script beside a fresh stylesheet, collapse the overlay.

Under the dev harness's strict policy, Chrome reports the shadow `<style>` element as a blocked inline style and applies the constructed sheet instead. That console line is expected there and is not a bug.

Safari on iPad caches an extension's scripts across app reinstalls until Safari is force-quit. After installing a new build, quit Safari from the app switcher and reopen it, or the previous script keeps running.

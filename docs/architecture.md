# Architecture

The mechanisms shared by every feature. Feature specs say what happens; this file says how. One H2 per mechanism.

## Pieces

| Piece | File | Job |
|---|---|---|
| Content script | `extension/content.js` | Everything: modes, input, rendering, anchoring, storage, toolbar. Top frame only. |
| Content styles | `extension/content.css` | The overlay canvases and the shadow host. Nothing else. |
| Background | `extension/background.js` | Relays the Safari toolbar button tap to the content script. |
| Manifest | `extension/manifest.json` | Manifest v3. Permissions: storage, activeTab, host `<all_urls>`. |
| Wrapper app | `Inkover/` | Generated by `xcrun safari-web-extension-converter`. Holds no logic. Regenerate rather than edit. |

No bundler, no dependencies, no build step. The content script is one file, organised into sections whose headings match the H2s below.

## Mode state machine

Three states, per tab: Off, View, Draw. Transitions and their triggers are the behaviour rules in [[modes-and-lock]]. The state lives in one variable; every other section reads it and never writes it. Entering Off removes the canvases and toolbar host from the DOM. Entering View or Draw creates them if absent.

## Input routing

The overlay canvases always have `pointer-events: none`. Nothing is ever blocked by the canvas itself. Capture is done with listeners on `window` in the capture phase:

- `pointerdown`, `pointermove`, `pointerup`, `pointercancel`: when the mode is Draw and `pointerType === "pen"`, call `preventDefault()` and `stopImmediatePropagation()`, then feed the active tool. Otherwise do nothing and let the event through.
- `touchstart`, `touchmove`, `touchend`, registered with `passive: false`: when the mode is Draw and any changed touch has `touchType === "stylus"`, call `preventDefault()`. This is what stops Safari from scrolling, selecting text or starting Scribble from a Pencil contact. Finger touches are never touched.
- Events whose `composedPath()` includes the toolbar host are always let through, in every mode.
- `keydown` for Escape, Cmd+Z and Shift+Cmd+Z, only when `document.activeElement` is body or null.

Use `getCoalescedEvents()` on `pointermove` when present. Pressure comes from `event.pressure`.

Iframes do not bubble events to the parent, so in Draw mode a shield `div` with `pointer-events: auto` is placed over the bounding rect of every visible iframe, re-measured on every render. Shields carry the same pen listeners; finger touches on a shield scroll the parent page because the shield does not prevent them.

## Coordinates and rendering

Two canvases, both `position: fixed`, sized to the visual viewport, scaled by `devicePixelRatio`:

- Ink canvas: all visible strokes. Redrawn in full whenever anything moves. A full redraw of 2,000 strokes is well under one frame.
- Trail canvas: only the trail. Runs its own `requestAnimationFrame` loop while segments exist.

Points arrive in client coordinates and are converted immediately to document coordinates using `visualViewport.offsetLeft`, `offsetTop`, `scale` and the layout scroll offsets, so a stroke drawn while a finger scrolls follows the content. At render time each stroke's points are mapped back through the current anchor rect and visual viewport into canvas pixels.

Redraw triggers, all coalesced into one `requestAnimationFrame`: `scroll`, `resize`, `visualViewport` `scroll` and `resize`, orientation change, the mutation observer, the resize observers, and any change to ink. A 1 s interval is a safety net for layout changes nothing observed.

Pen strokes are drawn as a filled outline built from per-point widths, midpoint-smoothed with quadratic curves. Highlighter strokes are one stroked path at fixed width with `globalAlpha` applied to the path as a whole.

## Anchoring

Behaviour and edge cases are in [[anchoring]]. The mechanism:

1. Candidate: `document.elementsFromPoint()` at the stroke's first point, skipping Inkover's own nodes. Walk up from the top-most hit until an element is block-level, at least 16 px tall, and has non-empty text or is `img`, `video`, `canvas`, `svg` or `picture`. Reaching `body` means anchor kind `root`.
2. Locator: if the element has an id unique in the document, kind `id`. Otherwise kind `path`, a selector built from tag and `:nth-of-type` from the nearest unique-id ancestor or `body`. Always store `text`: the first 60 characters of the element's normalised text content, and `width`: the element's bounding width at draw time.
3. Resolve: look up by id or path, verify `text` matches. On failure, scan `document.querySelectorAll(tag)` for the first element whose normalised text starts with `text`, and rewrite the locator. Resolutions are cached per stroke and dropped on every mutation batch.
4. Visible: the element is connected, `checkVisibility()` is true, and its rect has non-zero size. Otherwise the stroke is skipped this frame.
5. Position: `x = rect.left + dx × rect.width / width`, `y = rect.top + dy`.

One `MutationObserver` on `document.body` watches `childList`, `subtree`, and the attributes `class`, `style`, `hidden`, `aria-hidden`, `aria-selected`, `aria-expanded`, `open`. One `ResizeObserver` observes every distinct resolved anchor. Re-resolution is rate limited to once per 100 ms.

## Storage

`browser.storage.local`, key `ink:<page key>`, value `{ v: 1, strokes: [...] }`. Global settings live under key `settings`: tool, pen colour, highlighter colour, size, toolbar position, toolbar edge. Saves are debounced 500 ms and flushed on `pagehide`. Rules for limits and versions are in [[persistence]].

## Stroke model

```js
{
  id: "uuid",
  tool: "pen" | "highlighter",
  color: "black",              // palette key, see toolbar spec
  size: "s" | "m" | "l",
  straight: false,             // highlighter snap applied
  anchor: { kind: "id" | "path" | "root", value: "...", text: "...", width: 612 },
  points: [[dx, dy, pressure], ...],   // CSS px relative to anchor top-left
  created: 1757030400000
}
```

Undo entries are `{ type: "add" | "remove" | "clear", strokes: [...] }`. The eraser and Clear produce `remove` and `clear`; they never store anything themselves.

## Toolbar host

One `div` appended last in `body`, `position: fixed`, maximum z-index, holding an open shadow root with the toolbar markup and its own stylesheet. The host is re-appended if a mutation batch finds it disconnected. Its position is stored relative to the visual viewport edge it is snapped to, so it survives rotation.
